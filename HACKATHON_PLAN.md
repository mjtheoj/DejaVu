## 1. Problem Understanding
- [ ] Copy the official problem statement and constraints
- [ ] Identify target users and the core problem
- [ ] List required deliverables and judging criteria
- [ ] Define the smallest demonstrable solution (MVP)

## 2. Solution Design
- [ ] Compare feasible approaches
- [ ] Select the technology stack based on the problem
- [ ] Sketch the system architecture and data flow
- [ ] Identify APIs, datasets, models, and external dependencies
- [ ] Record assumptions and risks

## 3. Implementation
- [ ] Set up the repository structure and development environment
- [ ] Divide work into modules and assign owners
- [ ] Implement the critical end-to-end user journey first
- [ ] Keep configuration and secrets out of version control
- [ ] Commit small, clearly named changes

## 4. Validation
- [ ] Test the main user journey
- [ ] Test invalid inputs and failure cases
- [ ] Verify setup instructions on a clean environment
- [ ] Prepare a fallback demo path

## 5. Submission
- [ ] Complete the README with setup and run instructions
- [ ] Add architecture and workflow diagrams if useful
- [ ] Document limitations and future improvements
- [ ] Prepare the demo script and judging presentation

## Working Rules
- Prefer a working end-to-end MVP over a broad set of unfinished features.
- Do not add a technology until the problem requires it.
- Never commit API keys, passwords, access tokens, or .env files.
- Validate changes before considering a feature complete.
